# 绿泥石吸收波长仲裁逻辑专项审计

> 日期：2026-11-18  
> 当前代码：`cramm/classifier.py`  
> 当前窗口：`cramm/data/rf.json`  
> 复核数据：`output/synthetic_emit_v2/` 与 `output/synthetic_emit_ablation_v3/`（生产 float32 波长/FWHM）  
> **边界：参考谱衍生结果用于执行与敏感性审计，不是独立亚型精度评价。chl13 为内部校准记录，不能替代外部验证。**

## 1. 窗口与参考中心

四个纯绿泥石规则按左闭右开 `[lo, hi)` 窗口无缝覆盖 2.244–2.266 µm：

| 规则 | 窗口 (µm) | 宽度 (nm) | 1 nm 中心 (µm) | 生产 EMIT 中心 (µm) | 距最近边界 (nm) | 清洁自检 |
|---|---|---:|---:|---:|---:|---|
| lowFe | [2.244, 2.248) | 3 | 2.245063 | 2.245630 | 1.630 | 正确，无翻转 |
| clinochlore | [2.248, 2.252) | 4 | 2.249128 | 2.249596 | 1.596 | 正确，无翻转 |
| clinochlore_Fe | [2.252, 2.256) | 4 | 2.254511 | 2.254576 | 1.424 | 正确，无翻转 |
| thuringite | [2.256, 2.266) | 10 | 2.258744 | 2.259090 | 3.090 | 正确，无翻转 |

这些中心由各规则 feat0 的连续统端点和三点抛物线估计，是自洽性锚点，不是独立化学真值。前三类窗口宽度只有 3–4 nm，小于 2.25 µm 附近约 7.4 nm 的 EMIT 波段间距；抛物线可插值出亚波段中心，但不能消除噪声位移。

## 2. 实际执行逻辑

1. 所有规则先完成诊断、排除和 weighted constraints；绿泥石四条纯规则不携带 CRAMM 深度比字段。
2. weighted-fit argmax 产生原赢家。
3. 只有原赢家属于四条带窗纯绿泥石规则、fit > 0 且 `chl_center` 有效时，才进入绿泥石仲裁。
4. 中心出所有窗口或命中多窗时保持原赢家；唯一命中另一窗口时，目标规则还必须在仲裁前通过约束且 fit > 0。
5. 翻转后按目标规则 feat0 端点重估一次中心，不迭代；若重估非有限或越出目标窗口，则回退翻转前的有效中心，避免标签—中心不一致。
6. `chlorite+muscovite_mix_intimate`、`clinochlore_Fe.3+muscovite.7` 等混合规则不属于纯绿泥石仲裁组，保持原归属。

代码中旧的“重叠容差窗口”注释已与当前无缝窗口不一致，本次已修正。自定义孤儿窗口、非法窗口和单成员活跃组会在构造或缓存失效时明确报错。

## 3. 执行与不变量核验

生产 dtype 数据上：

- M00→M01 有 **14 次绿泥石翻转**；M10→M11 同样有 **14 次**，与深度比无关。
- 所有翻转目标在仲裁前均已通过约束，验收失败 **0**。
- 翻转前后触发状态变化 **0**。
- 14 次翻转后的中心全部仍位于目标窗口，未发现标签—中心状态不一致。
- 重拟合中心的最大位移为 **0.141 nm**。
- 编译/直接路径、串行/并行和族锁定专项测试均通过。
- 生产 float32 与早期 float64 上采样数据的绿泥石仲裁结论不变。

M00→M01 的转移构成：

| 转移 | 次数 |
|---|---:|
| clinochlore_Fe → thuringite | 6 |
| clinochlore_Fe → clinochlore | 5 |
| clinochlore → clinochlore_Fe | 2 |
| thuringite → clinochlore_Fe | 1 |

当前合成集没有 lowFe 目标翻转，因此它不能证明低铁纠正的收益。归档 EMIT 生产普查曾记录 133 次 `clinochlore → chlorite_lowFe`，见 `docs/arbitration_stats.md`；这是另一条归档证据，不应与当前合成计数混合。

### 3.1 lowFe 下边界扩展的受控结果（2.245 → 2.244 µm）

- 同一批 3,623 条生产 dtype 合成光谱中，新旧窗口的所有标签和中心完全不变，说明没有合格赢家利用新增区间。
- 当前代码的整景受控对照中，旧窗口有 135 次 clinochlore→lowFe，新窗口有 146 次；仅新增 **11 次**该方向翻转。
- 绿泥石总翻转由 16,250 增至 16,261；其他标签不变，跨族变化为 0。
- 新增 11 个像元的翻转前中心均位于 2.244–2.245 µm。
- 其中 2 个像元按 lowFe 端点重估后轻微越出 2.244 µm 下边界。新增目标窗口后验回退后，标签保持 lowFe，中心逐位回退到翻转前有效值。
- 旧归档的 133 次与当前旧窗口复核的 135 次属于不同归档/引擎状态，不能用其差值评价本次窗口修改。

## 4. 唯一明确退化：2.252 µm 边界跨越

`SYN00686` 的真实来源和 M00 赢家均为 `clinochlore`：

| 项目 | 数值 |
|---|---:|
| 清洁参考中心 | 2.249596 µm |
| 同连续统、无噪声中心 | 2.249599 µm |
| 加噪后中心 | 2.254177 µm |
| 噪声导致的偏移 | +4.579 nm |
| 连续统斜率本身的偏移 | +0.0026 nm |
| 跨越边界 | 2.252 µm |
| 错误中心超过边界 | 2.177 nm |
| 正曲率 / 顶点在三点区间内 | 是 / 是 |
| M00 / M01 fit | 0.9777 / 0.9237 |

结果是 `clinochlore → clinochlore_Fe`，由正确变为错误。该中心是合法抛物线顶点，存储与独立重算完全一致；没有缓存、目标验收或重拟合绕过。直接原因是噪声将中心推过无缝硬边界，而当前仲裁没有边界余量或不确定度门控。

这一条错误中心已超过边界 2.177 nm，1–2 nm 的余量无法阻止它；不能根据单一样本直接选择 3 nm 或其他新阈值。

## 5. lowFe 的额外边界与打分不对称

### 5.1 低余量与出窗保守策略

lowFe 的生产 EMIT 参考中心为 2.245630 µm。扩展前距 2.245 µm 下限仅 0.630 nm；2026-11-18 将下限扩展至 2.244 µm 后，距新下限为 1.630 nm，距最近边界为 1.630 nm。

当前逻辑对全局窗口之外的中心采取保守保持：

- 中心低于 2.244 µm 时，不会从 clinochlore 翻回 lowFe；
- 中心达到或高于 2.266 µm 时，也不会从 clinochlore_Fe 翻到 thuringite。

这避免把未覆盖区间的中心强行分类，但也意味着极端低铁或极端高铁的纠正能力受到窗口覆盖范围限制。它是设计边界，不是代码漏执行。

### 5.2 lowFe 的 feat2 压分

四条规则中只有 lowFe 携带第三个 VNIR 诊断特征，权重结构为 `0.0×fit0 + 0.7×fit1 + 0.3×fit2`，其余三条为 `1.0×fit1`。归档实测表明 feat2 会产生系统性低分，减少 lowFe 的原 argmax 胜出机会。

因此需要区分：

- **原 argmax 阶段**：lowFe 标签可能被 feat2 系统性低估；
- **仲裁阶段**：若纯绿泥石赢家的中心进入 lowFe 窗口，仍可翻回 lowFe；
- **中心产品**：`chl_center` 是连续输出，不能只看离散 lowFe 标签。

该不对称性来自官方规则继承，详见 `docs/lowfe_feat2_bias.md`。本次未改变其行为。

`docs/_audit_arbitration.py` 已补充并通过：

- 2.248 µm：命中右侧 clinochlore；
- 2.252 µm：命中右侧 clinochlore_Fe；
- 2.256 µm：命中右侧 thuringite；
- 低于 2.244 µm：保持原赢家；
- 达到 2.266 µm：保持原赢家；
- 2.244–2.245 µm 新增区间：可从 clinochlore 翻转至 lowFe；
- 重拟合非有限或越出目标窗：回退翻转前中心。

连同既有目标 fit、无窗成员、族锁定和重拟合检查，结果为 **ALL PASS**。日志：`output/chlorite_arbitration_audit.log`。

## 7. 结论与建议

**绿泥石仲裁预设逻辑能够运行，未发现实现绕开。** 当前主要风险为：

1. 3–4 nm 窄窗口对亚波段中心噪声敏感；
2. 全局窗口之外的保守保持限制了极端亚型纠正；
3. lowFe 在 argmax 阶段存在独立的 feat2 打分不对称；
4. 当前合成集缺乏 lowFe 目标翻转和独立化学真值。

后续应分别评价仲裁边界余量、lowFe 原赢家保留和混合规则排除策略，不能用单一总体精度掩盖这些不同机制。
